Large Scale Wave Energy Farm Dataset
===================================

Overview
--------

The main purpose of research on wave energy harvesting is to develop and implement technologies that can generate energy from the movement of the ocean. Wave energy harvesting systems are designed to extract energy from the wave energy that is generated by the movement of the ocean.
The primary benefits of wave energy harvesting are that it is a renewable and sustainable source of energy, which can reduce the reliance on fossil fuels and help mitigate the effects of climate change. Additionally, wave energy harvesting systems can be installed on a wide range of locations, including coastal areas, islands, and offshore platforms, making them a versatile and scalable solution for renewable energy.

Overall, the research on wave energy harvesting aims to address the challenges of renewable energy and develop technologies that can be used to generate energy from the movement of the ocean.

This repo folder contains the "Large Scale Wave Energy Farm" dataset files (from UCI). The provided CSVs describe WEC farm layouts (device coordinates) and per-device power outputs computed for multiple scenario samples.

Source & citation
------------------

- Source: UCI Machine Learning Repository — Large Scale Wave Energy Farm. Please cite the original authors and the UCI entry when publishing.

Files included
----------------------

All files are under `data/WEC/`:

- `WEC_Perth_49.csv`  — 49-device layout (Perth)
- `WEC_Perth_100.csv` — 100-device layout (Perth)
- `WEC_Sydney_49.csv` — 49-device layout (Sydney)
- `WEC_Sydney_100.csv`— 100-device layout (Sydney)

Schema summary
--------------

Each CSV follows the same structural pattern with two variants (49- and 100-device):

- Coordinate columns: `X1,Y1,X2,Y2,...` — device coordinates (units: metres in original dataset). 49-file variants contain X1..X49,Y1..Y49; 100-file variants contain X1..X100,Y1..Y100.
- Per-device outputs: `Power1,Power2,...,PowerN` — instantaneous power (W) produced by each device (N = 49 or 100).
- Aggregate columns: `qW` (auxiliary) and `Total_Power` — farm total power (W).

Rows represent independent scenario samples (environmental/operational configurations). There is no timestamp column in these CSVs — treat each row as a separate sample.

Data Checks
-----------------------------

1. Confirm shapes and headers: list files and print the first row/columns.
2. Sanity check: verify that the sum of `Power*` columns equals `Total_Power` (or is very close) for sample rows.
3. Check for missing values in coordinate/power columns.

Pandas Quick Start
----------------------------

```
import pandas as pd
from pathlib import Path

data_dir = Path('data/WEC')
files = sorted(data_dir.glob('WEC_*.csv'))

for f in files:
	df = pd.read_csv(f)
	print(f.name, df.shape)
	print('First columns:', list(df.columns[:10]))

# Example: verify power sum for a 100-device file
df = pd.read_csv(data_dir / 'WEC_Perth_100.csv')
power_cols = [c for c in df.columns if c.startswith('Power')]
df['power_sum'] = df[power_cols].sum(axis=1)
print('Max abs diff between power_sum and Total_Power:', (df['power_sum'] - df['Total_Power']).abs().max())
```

Use cases & modelling notes
---------------------------

- Typical tasks: predict `Total_Power` from layout + environmental descriptors; per-device power estimation; layout sensitivity and optimization.
- If you want a single model covering both 49- and 100-device layouts, either pad/mask missing device columns or train separate models per layout size.
- Spatial feature ideas: device coordinates, distances between devices, nearest-neighbour aggregates, and radial basis features. Consider graph/point-cloud models for device interactions.

Data cleaning recommendations
---------------------------

- Drop or impute rows with missing coordinate or power values. If only a few devices are missing, decide whether to impute zeros or use a per-device mask.
- Scale/normalize coordinates before feeding them to ML models (centering on farm centroid helps some models).
- Verify units (meters, Watts) against the original UCI page or paper before reporting results.
